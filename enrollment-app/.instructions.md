# Enrollment App: Development Conventions

## Project Overview

**Capoeira Enrollment App** manages student registrations for capoeira courses with:
- Student account management (registration, login)
- Course catalog (regular and special courses)
- Enrollment system with email notifications
- Admin dashboard for instructors/admins

## API Conventions

### Authentication

All protected routes require JWT token in Authorization header:

```
Authorization: Bearer <token>
```

Tokens are stored in localStorage:
- `adminToken`: For admin users
- `studentToken`: For student users

### Response Format

**Success Response (200):**
```json
{
  "data": { /* response data */ },
  "message": "Success message",
  "token": "optional-jwt-token"
}
```

**Error Response (4xx/5xx):**
```json
{
  "error": "Error description"
}
```

### Endpoint Categories

| Category | Path | Access | Purpose |
|----------|------|--------|---------|
| Student Auth | `/api/auth/*` | Public | Student registration/login |
| Admin Auth | `/api/admin/auth/*` | Admin | Admin login/management |
| Courses | `/api/courses/*` | GET: Public, POST/PUT/DELETE: Admin | Course CRUD |
| Enrollments | `/api/enrollments` | Student (create), Admin (view/cancel) | Student enrollment |
| Dashboard | `/api/dashboard/*` | Admin only | Statistics and management |
| Attendance | `/api/attendance/*` | Admin | Attendance tracking |

## Database Schema

### Key Models

```prisma
// Users (Admin)
model User {
  id, email, password, name, role
}

// Students
model Student {
  id, email, password, firstName, lastName, phone, birthDate, age
  enrollments[], attendance[]
}

// Courses (Regular + Special)
model Course {
  id, name, description, level, type
  dayOfWeek (for regular), date (for special)
  startTime, endTime, maxStudents
  enrollments[]
}

// Enrollments (Many-to-Many)
model Enrollment {
  id, studentId, courseId, status, enrolledAt
  student, course
}

// Attendance Tracking
model Attendance {
  id, enrollmentId, studentId, date, present
}
```

## Course Schedule & Pricing

### Default Course Schedule

| Day | Course | Time | Duration | Price |
|-----|--------|------|----------|-------|
| Sunday | Children & Family | 10:30-11:30 | 1 hour | £8 |
| Thursday | Beginner Adult | 18:30-19:30 | 1 hour | £8 |
| Thursday | Intermediate Adult | 18:30-19:30 | 1 hour | £8 |

### Pricing Model

- **Base Rate**: £8 per class/session (fixed for all courses)
- **Calculation**: `(end_time - start_time_in_hours) × £8`
- **Examples**:
  - 1 hour course = £8
  - 1.5 hour course = £12
  - 2 hour course = £16

### Payment Information

- **When**: Due on the day of the course (on-site)
- **How**: Cash or bank transfer (no online payment)
- **Who processes**: Instructor handles payment collection

### Cancellation Policy

- **Allowed**: Up to 24 hours before course start
- **Penalty**: None (free cancellation)
- **How**: Student self-service via app or contact instructor
- **Charge**: No charge for advance cancellations

## Frontend Conventions

### Component Structure

**Admin Components** (`frontend/components/admin/`):
- `DashboardHeader.tsx` - Header with logout
- `EnrollmentStats.tsx` - Statistics overview
- `CourseList.tsx` - Display courses with edit/delete
- `CourseForm.tsx` - Modal for create/edit course

### Styling

- Use **TailwindCSS** for all styling
- Color scheme: Amber/Orange (Capoeira theme)
  - Primary: `amber-600`, `amber-700`, `amber-800`
  - Success: `green-600`
  - Error: `red-600`
  - Text: `gray-800`, `gray-600`

### API Interaction

All API calls go through `lib/api.ts`:

```typescript
import { apiClient } from '@/lib/api';

// Example usage
const response = await apiClient.createCourse(courseData);
if (response.error) {
  // Handle error
} else {
  // Handle success
}
```

### Protected Routes

Admin dashboard is protected - redirects to login if not authenticated:

```typescript
useEffect(() => {
  const checkAuth = async () => {
    const response = await apiClient.getAdminProfile();
    if (response.error) router.push('/admin/login');
  };
  checkAuth();
}, []);
```

## Backend Conventions

### Route Structure

```typescript
// routes/courses.ts
router.get('/', async (req, res) => { /* public */ });
router.post('/', adminOnly, async (req, res) => { /* protected */ });
router.put('/:id', adminOnly, async (req, res) => { /* protected */ });
router.delete('/:id', adminOnly, async (req, res) => { /* protected */ });
```

### Middleware

- `authenticate`: Requires valid JWT (any role)
- `authorize(roles)`: Requires specific role
- `adminOnly`: Shorthand for admin-only routes

### Error Handling

```typescript
try {
  const result = await prisma.model.findUnique(...);
  if (!result) return res.status(404).json({ error: 'Not found' });
  res.json(result);
} catch (error) {
  console.error('Error:', error);
  res.status(500).json({ error: 'Operation failed' });
}
```

### Email Service

Use `emailService` for all email communications:

```typescript
import { emailService } from '../services/emailService';

// Send confirmation to student
await emailService.sendStudentEnrollmentConfirmation(
  studentEmail,
  studentName,
  courseName,
  courseDate,
  courseTime
);

// Notify instructor
await emailService.sendInstructorNotification(
  instructorEmail,
  studentName,
  studentEmail,
  courseName,
  courseDate,
  courseTime
);
```

## Common Development Tasks

### Add New Endpoint

1. Create/update route file in `backend/src/routes/`
2. Implement handler function
3. Add middleware for auth if needed
4. Register route in `server.ts`
5. Test with curl or Postman
6. Update API client in `frontend/lib/api.ts`

### Add Admin Feature

1. Create component in `frontend/components/admin/`
2. Add tab/section in dashboard page
3. Implement API calls via `apiClient`
4. Add styling with TailwindCSS
5. Test admin access control

### Modify Database Schema

1. Update `backend/prisma/schema.prisma`
2. Run: `npx prisma migrate dev --name description`
3. Regenerate client: `npx prisma generate`
4. Update types in backend if needed

### Add Email Template

1. Update/add method in `backend/src/services/emailService.ts`
2. Design HTML email template
3. Call from appropriate route/controller
4. Test with real email or test service

## Performance Tips

1. **Database Queries**
   - Use `include` in Prisma to fetch relations in one query
   - Avoid N+1 queries

2. **Frontend**
   - Use `useCallback` for memoized functions
   - Lazy load components if heavy
   - Optimize images

3. **API**
   - Implement pagination for large lists
   - Use appropriate HTTP status codes
   - Add input validation before DB queries

## Security Best Practices

1. **Authentication**
   - Passwords hashed with bcryptjs (10+ rounds)
   - JWT tokens have expiration time
   - Never store passwords in logs

2. **Authorization**
   - Check role on every protected endpoint
   - Verify user owns resource (if applicable)
   - Use `adminOnly` middleware consistently

3. **Data Validation**
   - Validate email format
   - Validate required fields
   - Sanitize user input

4. **CORS**
   - Configured to frontend URL only
   - No credentials unless needed
